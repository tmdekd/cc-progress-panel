# 진행 패널 진행선 모양 설계 (2026-11-24)

## 왜

- 패널 아래 실행 중 칸의 명령이 위 단계와 떨어져 있어, 어느 단계의 일인지 짐작해야 했다.
- 진행률이 숫자 한 줄과 막대 한 줄로 두 줄을 썼다.
- 주황(claude 색)이 묶음 이름·단계·시간에 퍼져, 정말 지금 하는 한 줄이 덜 튀었다.
- 사용자 요청: UI/UX·배치·레이아웃·색을 손봐 보기 좋게. 시안 4개(지금, A 정돈, B 진행선, C 지금 카드)를 그려 비교했고, 사용자가 "B에 A의 진행률 막대"를 골랐다.
  - 시안 페이지: https://claude.ai/artifact/1HdorFdVCH91f8KEGTpiJG

## 목표

- 지금 어디쯤인지 왼쪽 세로선만 봐도 알 수 있다.
- 돌고 있는 명령이 어느 단계의 일인지 한눈에 보인다.
- 진행률은 한 줄.

## 하지 않는 것

- 입력창 위 알림 상자는 그대로 둔다.
- 짧게 보기 규칙(진행 중·막힘은 모두, 끝난 것 최근 1개, 예정 3개, 높이 모자라면 FITS 순서로 줄임)은 그대로 둔다.
- 시간 규칙(일한 시간만, 30초마다 다시 그림, 1분 전 `방금 시작`)은 그대로 둔다.
- 명령 이름 규칙(파일·검색 도구 "종류: 대상", 같은 종류 한 줄 묶기, Bash 설명)은 그대로 둔다.

## 실패로 보는 것

- 패널 높이를 넘겨 스크롤이 생긴다.
- 36칸 패널에서 줄이 폭을 넘는다.
- 밝은 테마에서 색이 안 보인다(테마 색 이름만 쓰므로 생기지 않아야 한다).

## 검토한 방법

| 안 | 내용 | 얻는 것 | 잃는 것 |
|---|---|---|---|
| A 정돈 | 한 줄 진행률, 지금 줄 바탕색, 명령 두 톤 | 앞서 정한 모양 유지 | 단계와 명령이 여전히 따로 |
| B 진행선 | 왼쪽 세로선 색으로 위치 표시, 명령을 지금 단계 아래에 | 명령과 단계가 이어짐, 순서 유지 | "아래 칸은 `- 하는 일` 목록만"(11/18 결정)이 바뀜 |
| C 지금 카드 | 지금 단계를 테두리 상자로 맨 위에 | 지금 일이 가장 크게 보임 | 테두리가 4칸을 써서 이름이 많이 잘림, 계획 순서 흐려짐 |

사용자 선택: **B + A의 진행률 막대**.

## 모양

```
진행 패널 실행 중 칸 요약 표시
━━━━━━━━━━━━━━━━━──────── 4/7 · 23분째

┆ 완료 3개 더
│
◉ 구현·테스트                  6분째
│ ● 실패 테스트 작성             4분
│ ◉ 표시 규칙·묶기 구현        2분째
│ ┆ 파일 읽기 register.tsx 외 1개
│ ┆ 코드 검색 "labelOf"
│ ○ 전체 테스트·검증
│
○ 설치본·저장소 반영
```

### 머리

- 1줄: 제목(굵게).
- 2줄: 가는 막대 + `완료수/전체` 굵게 + ` · 전체 시간` 흐리게. 막대 폭은 줄 폭에서 오른쪽 글자와 빈칸 하나를 뺀 만큼. 끝난 몫은 `━`(success), 나머지는 `─`(subtle). 다 끝나면 막대 전체가 초록.
- 3줄: 빈 줄. 진행률 요소(Progress)는 쓰지 않는다. `HEAD_ROWS`는 4에서 3으로.

### 단계 표시와 색

| 상태 | 표시 | 표시 색 | 이름 | 시간 |
|---|---|---|---|---|
| 끝남 | ● | success | 흐리게 | 흐리게 |
| 진행 중 | ◉ | claude | claude 굵게 | claude |
| 예정 | ○ | subtle | 보통 | 흐리게 |
| 막힘 | ▲ | warning | warning 굵게 | warning |
| 건너뜀 | – | subtle | 흐리게 줄 긋기 | 흐리게 |

- 묶음 이름: 끝났거나 건너뛰었으면 흐리게, 아니면 기본 색 굵게(주황 아님). 묶음 시간은 진행 중·막힘이면 그 상태 색, 아니면 흐리게.

### 세로선

- 맨 위 단계 표시는 0번째 칸에 놓이고, 묶음 안 줄은 0번째 칸에 `│`, 2번째 칸에 아래 단계 표시가 온다.
- 선 색은 보이는 맨 위 묶음 차례로 정한다. 처음 끝나지 않은 묶음을 "지금 묶음"이라 한다.
  - 지금 묶음보다 앞: success.
  - 지금 묶음 안: 지금 묶음이 진행 중이면 claude, 막힘이면 warning, 예정이면 subtle.
  - 지금 묶음보다 뒤: subtle.
  - 다 끝났으면 모두 success.
- 맨 위 묶음 사이 빈 줄은 `│` 한 줄로 바꾼다. 색은 다음 묶음으로 가는 길이 지나온 길이면 success, 아니면 subtle. 지나온 길: 다음 묶음이 지금 묶음보다 앞이거나, 지금 묶음이면서 진행 중·막힘일 때. FITS의 `gaps: false`이면 이 줄을 뺀다.
- 숨긴 끝난 단계: 맨 위에 `┆ 완료 n개 더`(┆ success, 글자 흐리게), 이어서 `│`(success) 한 줄(`gaps: false`이면 뺌).
- 숨긴 예정: 맨 아래에 `│`(subtle) 한 줄(`gaps: false`이면 뺌), `┆ 예정 n개 더`(┆ subtle, 글자 흐리게).

### 단계 아래에 붙는 줄

- 붙는 자리 앞부분: 맨 위 단계면 `┆ `(그 단계 상태 색), 묶음 안 단계면 `│ ┆ `(│는 그 묶음의 선 색, ┆는 그 단계 상태 색). 붙는 글자는 단계 이름과 같은 칸에서 시작한다.
- 막힘 이유 등 메모: 막힘이면 warning, 아니면 흐리게.
- 돌고 있는 명령: 진행 중 단계 가운데 가장 최근에 시작한 단계 아래. 종류(`파일 읽기:`처럼 쌍점까지)는 흐리게, 대상은 보통. 쌍점은 `에이전트: …`·`스킬: …` 같은 다른 명령 이름과 맞추려고 남긴다(시안 그림에는 없었음). 대상은 지금처럼 폭에 맞춰 `외 n개`. 5줄까지, 넘으면 `외 n개` 줄(같은 앞부분, 흐리게).
- 진행 중 단계가 하나도 없거나 목록이 없으면, 명령은 맨 아래 빈 줄 하나 뒤에 `┆ `(subtle) 앞부분으로 붙는다.
- 돌고 있는 명령이 없으면 아무 줄도 두지 않는다. 구분선(`────`)과 "실행 중인 작업 없음" 줄은 없앤다.
- 진행 중 단계가 짧게 보기에서 숨는 일은 없다(진행 중·막힘은 늘 보인다).

## 테스트 (모두 빠른 테스트, `claude plugin test`)

1. 머리: 2줄째가 `━`·`─` 막대 + `4/7 · 23분째`이고 폭이 패널 폭과 같다. Progress 요소가 없다. 다 끝나면 `━`만 있고 `─`가 없다.
2. 상태별 표시·색: 위 표대로(터미널·데스크톱).
3. 세로선 색: 지나온 곳 success, 지금 묶음 안 claude(막힘이면 warning), 뒤 subtle. 다 끝나면 모두 success.
4. 명령 자리: 진행 중 단계 아래에 `│ ┆ 파일 읽기 …`. 진행 중 단계가 없으면 맨 아래. 명령이 없으면 명령 줄·구분선·"실행 중인 작업 없음"이 없다. 둘 이상 진행 중이면 가장 최근에 시작한 단계 아래.
5. 막힘 이유가 그 단계 아래에 warning으로.
6. 기존 테스트(짧게 보기, 시간, 알림, 저장·이어받기, 명령 이름)는 계속 통과. 모양만 바뀐 기대값(표시 글자, `- ` 머리, 구분선, 줄 수)은 새 모양으로 고친다.
