# 패널 높이에 따라 늘리기 설계

2026-11-25. 짧게 보기는 끝난 단계 1개, 예정 3개(+마지막 단계)로 고정되어 있다. 패널 높이에 여유가 있어도 더 보여 주지 않는다. 사용자가 늘리는 차례와 명령 줄 자리를 골랐다.

## 왜

`FITS`는 패널이 낮을 때 줄이기만 한다. 키가 큰 패널에서는 아래가 비어 있는데도 `┆ 예정 n개 더`, `┆ 완료 n개 더`로 접혀 보인다.

## 정한 것

- **늘리는 차례 (사용자 선택: 예정부터)**
  - 자리가 남으면 예정을 목록 차례로 하나씩 늘린다. 예정을 다 보일 때까지 끝난 단계는 늘리지 않는다.
  - 예정을 다 보인 뒤에도 남으면 끝난 단계를 최근에 끝난 것부터 늘린다. 같은 시각이면 목록에서 뒤의 것부터(지금 "가장 최근 1개"를 고르는 규칙과 같다).
  - 줄이는 차례(예정 3 → 2 → 1, 끝난 단계, 남은 예정, 마지막 단계, 세로선 줄, 개수 줄 하나로)는 그대로다.
- **명령 줄 자리 (사용자 선택: 2줄 비워 두기)**
  - 늘린 모양을 고를 때 명령 줄(▶ …)을 최소 2줄로 친다. 명령이 2줄 이하로 오가면 목록이 바뀌지 않는다.
  - 명령 줄이 3줄 이상이면 그만큼 줄여 스크롤이 생기지 않는다.
  - 기존 모양(예정 3개 이하)은 지금처럼 실제 줄로 센다. 낮은 패널에서 보이던 것이 줄지 않는다.
- 진행 중·막힘은 늘 보인다. 마지막 단계 규칙, 혼자 숨는 단계 규칙, 묶음 규칙은 바꾸지 않는다.
- 고르는 방식은 지금처럼 넉넉한 모양부터 그려 보고 들어가는 첫 모양이다. 더 넉넉한 모양이 더 짧을 때가 있으므로(숨은 끝남이 그린 묶음 안에 있을 때) 위에서부터 차례로 잰다.

## 테스트 (모두 빠른 테스트, `claude plugin test .`)

목록: 기획·조사·설계·시안(끝남, 이 차례로), 개발(진행 중), 화면·서버·연결·시험·문서·배포·공개(예정). 줄 수: 기본 18, 예정 4개 20, 예정 전부 22, +끝난 2개 24, 전부 26.

1. 높이 21 → 기본 모양(`┆ 예정 3개 더`). 22 → 예정 4개와 `┆ 예정 2개 더`. 24 → 예정 전부, 끝난 1개. 26 → `┆ 완료 2개 더`, 설계, 시안. 28·40 → 전부.
2. 끝낸 차례가 시안 → 기획 → 설계 → 조사이면 26에서 조사·설계가 보인다.
3. 높이 22에서 명령 1개, 2개 → 모양이 그대로이고 ▶ 줄만 는다.
4. 높이 22에서 명령 3개 → 기본 모양으로 줄고 넘치지 않는다.
5. 기존 테스트 가운데 높이 40에서 늘린 모양을 그리게 되는 것은 기대를 두고 높이를 그 모양의 줄 수로 고정한다. 모두 끝난 목록은 높이 40에서 전부 보이는 것으로 기대를 바꾼다.

화면 확인: 설치본에 복사한 뒤 위 목록을 띄우고 사용자가 캡처한다(높이 맞춤, 명령 실행 중, 모두 끝남).
