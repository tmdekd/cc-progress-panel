# 검토에서 미룬 것 정리 설계

2026-11-25. `2026-11-25-review-leftovers-design.md`를 고친 뒤 새 검토가 미룬 4건을 정한다. 사용자가 캡처로 지금 모양을 보고 권장안을 골랐다(시나리오 A·B·C).

## 왜

"줄 수가 같을 때만 개수 대신 그 단계를 그린다"는 규칙이 두 곳에서 어긋났다. 끝난 단계 하나는 줄을 늘릴 때도 그려지고, 묶음 안에서는 줄을 늘리지 않아도 그려지지 않는다. 원문자 쉼표 규칙은 한쪽 방향만 막았다.

## 정한 것

- **A. 끝난 단계 하나 (사용자 선택: 나뉘면 개수로)**
  - 숨길 끝난 단계가 1개뿐이고 맨 위 단계이며 메모가 없어도, 그 단계를 그리면 숨긴 예정 덩어리가 둘로 나뉘면 `완료 1개 더`로 센다.
  - 나뉘지 않으면 지금처럼 그 단계를 그린다.
  - 예: 준비(끝남, 최근)·자료·목차·초안·본문(진행 중)·표1·표2·그림(먼저 끝남)·부록1·부록2·인쇄 → `┆ 완료 1개 더`, `● 준비`, `○ 자료`, `○ 목차`, `○ 초안`, `◉ 본문`, `┆ 예정 4개 더`, `○ 인쇄`.
- **B. 원문자 뒤 보통 숫자 (사용자 선택: 숫자면 쉼표)**
  - 원문자를 바꾼 결과가 숫자로 끝나고 바로 뒤가 보통 숫자(0-9)이면 쉼표를 넣는다.
  - 예: `그림 ③4` → `그림 3,4`, `①②3` → `1,2,3`.
  - 영문자 뒤는 그대로 붙인다(`③a` → `3a`).
- **C. 묶음 안 혼자 숨는 단계 (사용자 선택: 이름으로 그리기)**
  - 이미 그리는 묶음 안에서 숨긴 예정 덩어리가 1개이고 메모가 없으면, 개수 대신 그 단계를 그린다. 묶음 머리가 이미 있으므로 줄 수가 같다.
  - 그리지 않는 묶음의 단계는 지금처럼 맨 위 덩어리의 개수에 든다. 그리면 묶음 머리 줄이 늘기 때문이다.
  - 예: 조사[자료 찾기(진행 중), 읽기, 요약, 비교, 정리], 작성[초안, 퇴고] → `├─○ 정리`, `├─○ 초안`으로 보이고 개수 줄이 없다.
- **D. `..` 경로:** 동작은 이미 맞다. 테스트만 더한다.
- 설계 문서(2026-11-25-review-leftovers-design.md) 17줄의 "건너뛸 때만 줄이 는다"를 바로잡는다.

## 테스트 (모두 빠른 테스트, `claude plugin test .`)

1. A 예시 목록, 패널 40×40 → 위 차례 그대로.
2. C 예시 목록, 40×40 → `◉ 조사`, `├─◉ 자료 찾기`, `├─○ 읽기`, `├─○ 요약`, `├─○ 비교`, `├─○ 정리`, `○ 작성`, `├─○ 초안`, `└─○ 퇴고`.
3. B: `그림 ③4 보기`, `①②3 비교`, `③a 확인`, `장 ④ 5절` → `그림 3,4 보기`, `1,2,3 비교`, `3a 확인`, `장 4 5절`.
4. D: 검색(pattern `baz`, path `C:/Users/me/..`, glob `*.md`) → `┆ ▶ 검색 "baz" · *.md`.
5. 기존 테스트 가운데 묶음 안 개수 1개를 기대하던 것은 그 단계 이름으로 기대를 바꾼다(C 때문). 나머지는 그대로 통과한다.

화면 확인: 설치본에 복사한 뒤 A·B·C 목록을 띄우고 사용자가 캡처한다.
